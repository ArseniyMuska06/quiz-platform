# Платформа для вебтестування

Вебзастосунок для створення та проходження тестів. Користувач може опублікувати тест у загальному каталозі або зробити його особистим. Після проходження сервер перевіряє відповіді та зберігає результат кожної спроби.

## Можливості

- **Реєстрація та вхід.** Користувач створює акаунт і входить за електронною поштою та паролем.
- **Публічний каталог.** Гості можуть переглядати тести та їхні описи. Якщо гість натисне «Почати тест», відкриється сторінка входу.
- **Конструктор тестів.** Автор задає назву, опис і видимість тесту, додає запитання з однією правильною відповіддю, кількома правильними відповідями або текстовою відповіддю.
- **Особисті тести.** На сторінці «Мої тести» автор бачить усі свої тести й може видалити будь-який із них. Особистий тест доступний лише автору.
- **Проходження.** Користувач може переходити між запитаннями й змінювати відповіді до підтвердження завершення.
- **Результати.** Після завершення користувач бачить оцінку у відсотках і розбір відповідей. На сторінці тесту відображаються його останній і найкращий результати. Кнопка «Пройти ще раз» відкриває перше запитання з порожніми відповідями.

## Перший запуск

Для запуску на Windows потрібні Git і Docker Desktop із Docker Compose. Команди нижче виконуються у PowerShell.

### 1. Завантаження проєкту

```powershell
git clone https://github.com/ArseniyMuska06/quiz-platform.git
cd quiz-platform
```

Якщо репозиторій уже завантажено, відкрий PowerShell у папці з файлом `compose.yaml`.

### 2. Налаштування середовища

Створи файл `server/.env`. Щоб побачити назву бази та ім’я користувача, вказані в `compose.yaml`, виконай із кореня проєкту:

```powershell
Select-String -Path .\compose.yaml -Pattern '^\s*POSTGRES_(DB|USER):'
```

Заповни `server/.env` за цим шаблоном:

```dotenv
PGHOST=db
PGPORT=5432
PGDATABASE=<значення POSTGRES_DB із compose.yaml>
PGUSER=<значення POSTGRES_USER із compose.yaml>
PGPASSWORD=<власний пароль бази даних>
SESSION_SECRET=<довгий випадковий рядок для підписування сесій>
```

Заміни всі значення в кутових дужках разом із самими дужками. Для `PGPASSWORD` і `SESSION_SECRET` використай два різні значення. Зберігай заповнений файл локально.

### 3. Запуск і перевірка

Відкрий Docker Desktop і дочекайся запуску Docker Engine. У корені проєкту виконай:

```powershell
docker compose --env-file .\server\.env up --build --watch
```

Команда запускає клієнтську частину, сервер і PostgreSQL. Під час першого запуску з порожнім томом PostgreSQL автоматично створює таблиці бази даних.

Відкрий [платформу в браузері](http://localhost:5174). Щоб перевірити роботу API, відкрий [сторінку стану сервера](http://localhost:5174/api/health). Очікувана відповідь — `{"status":"ok"}`.

Спочатку каталог порожній. Зареєструйся, увійди та створи публічний тест. Його картка з’явиться на головній сторінці.

## Щоденна робота

Після увімкнення комп’ютера запусти Docker Desktop і виконай ту саму команду `up --build --watch` із кореня проєкту. Залиш термінал відкритим під час розробки.

- Зміни у файлах `src/` автоматично відображаються в браузері.
- Після зміни файлів у `server/src/` Docker Compose синхронізує серверний код і перезапускає сервер.
- Щоб зупинити застосунок, натисни **Ctrl+C**. Акаунти, тести й результати зберігаються в іменованому томі PostgreSQL. Параметр `-v` у команді `docker compose down -v` видаляє том разом із даними.

## Як перевіряються відповіді

Під час проходження сервер надсилає текст запитань і варіанти відповіді. Поле `rightAnswer` залишається на сервері до завершення спроби.

| Тип запитання | Умова правильної відповіді |
| --- | --- |
| Одна відповідь | Користувач вибрав правильний варіант |
| Кілька відповідей | Вибрано всі правильні варіанти без зайвих. Порядок вибору довільний |
| Текстова відповідь | Текст збігається з еталоном після видалення крайніх пробілів і приведення до одного регістру |

Кожна правильна відповідь дає один бал. Пропущене запитання дає нуль балів і враховується в загальній кількості. Наприклад, одна правильна відповідь із трьох дає **33%**.

## Основні таблиці бази даних

| Таблиця | Що зберігає |
| --- | --- |
| `users` | Ім’я користувача, електронну пошту та хеш пароля |
| `tests` | Назву тесту, опис, автора, видимість і запитання |
| `attempts` | Користувача, тест, надані відповіді, кількість правильних відповідей, загальну кількість запитань і час завершення |

Кожна завершена спроба створює окремий запис у `attempts`. Завдяки цьому користувач може проходити тест повторно й бачити як останній, так і найкращий результат. Коли автор видаляє тест, разом із ним видаляються всі пов’язані спроби.
